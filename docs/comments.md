# 中文标签注释约定

## 适用范围

手写源代码的说明使用中文，并统一使用普通双斜线注释。此次整理仅覆盖指定的数学、几何、渲染、随机数、噪声、概率密度、采样、纹理、图像接口、测试及构建文件；不代表其他并行编辑文件已经完成迁移。

## 标签

- `// @brief`：接口用途、数据结构含义或简短的实现说明。
- `// @param 名称`：参数含义、单位、取值范围、输入输出方向或所有权；只写有帮助的内容。
- `// @return`：返回值、可空结果、错误或返回资源的释放责任；无返回信息时省略。
- `// @notice`：前置条件、生命周期、线程约束、兼容性、数值边界及已知限制。
- `// @method`：算法依据和推导，可使用 Markdown 与 LaTeX。行内公式用 `$...$`，独立公式用 `$$...$$`；多行公式的每一行也必须带此标签。

每一条说明行均带标签，包括续行、标题和公式行。不要混用无标签续行、三斜线文档注释或模块文档注释。允许在代码尾部使用带标签的短注释。无需为没有意义的参数、无返回值或显而易见的算术重复添加说明。

## 语言与准确性

说明文字使用中文；保留标识符、单位、协议名、算法名及公式中的技术符号。缩写首次出现时解释含义，例如概率密度（PDF）、包围体层次结构（BVH）及标准误差（SE）。不要为翻译注释修改标识符、字符串、测试名称或程序行为。

文档必须描述当前实现，而不是预期改进。保留并明确所有权、闭区间端点、退化输入、随机抽样和误差估计的局限。方向密度注明相对于立体角还是面积；不能将 Sobol 副本内相关点当作独立样本，也不能把自适应停止阈值宣称为有保证的置信区间。确定性说明应区分任务调度可复现与跨编译器、跨平台逐位一致。

## 检查方式

在本次允许修改的文件中检查每条注释是否具有上述标签、说明是否为中文，并将版权及许可声明单独豁免。代码审查应比较去除注释后的词法内容，确认字符串、测试名及执行逻辑未变；不能通过全仓库格式化来整理注释，以免干扰其他并行修改。
